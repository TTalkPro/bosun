# 全项目审查：缺陷修复与优化（2026-11-19）

升级 bitcask 时顺带把后端通读了一遍、前端做了一轮只读审查。下面是已修的和留着没动的。

## 已修 · 安全
- **只读 key 能轮换 / 撤销别的 key**：scope 表缺省放行，而 key handler 只看有没有 `:id`——`POST /keys/:id` 也轮换、`DELETE /keys/:id/rotate` 也撤销，这两条路径都不在表里。只读 key 可以借此换出同一用户更高权限 key 的明文。现在路由按 mode 分开，没登记的非只读方法一律要 `manage`。
- **导入可以跨组织写**：组织 B 的管理员上传一个写着组织 A 项目 key 的任务 / 反馈 / 关联（不带项目），原样落库，覆盖 A 的数据；同名操作者也会被划走。现在校验归属（见 designs/10）。
- **撤销的 key / 登出的会话 / 停用的用户可能被写回来**：`last_used_at`、`last_seen_at`、`last_login_at` 是整条记录脏写，和并发的撤销 / 轮换 / 登出 / 停用撞上会把旧状态盖回去。改成事务里重读再写。
- **key 的项目白名单漏了项目接口和导出**：受限 key 仍能列出 / 读取 / 修改全部项目、导出全组织；`project_keys: ["*"]` 反而什么都看不到。
- **改密 / 重置密码不踢会话**：旧会话继续有效 30 天。现在全部作废，当前浏览器换新 Cookie。
- **请求体没有总上限**：逐块累加，不用登录的接口也能被撑爆内存。现在 8 MB（导入 256 MB），超过 413。
- **`identify` 可以冒用别的用户的显示名**（署名即身份）：绑定了 key 的会话现在拒绝。
- 登录时不存在的邮箱算了两次 PBKDF2、存在的算一次，时间差反而暴露邮箱是否注册——改成各一次。

## 已修 · 正确性
- **BQL 500**：`priority IN (...)`、`<任意字段> IS EMPTY`（不支持的字段到逐条求值才抛）、不存在的日期（`2026-13-45`）、非法 UTF-8，都是未捕获异常。现在解析期拒绝并给可读的错误。
- **merge 导入让序号回退**：导入一份旧导出后项目 `task_seq` 变小，下一次建单会和已有任务撞号并**覆盖**它；反馈同理。序号改为只进不退，建单撞号返回 `{conflict, id}`。
- **导入不校验类型**：`labels: "x"`、`title: 42` 之类原样落库，之后一读就 500。
- **Epic 状态不跟步骤集合走**：给 DONE 的 Epic 加步骤、把没做完的步骤换走 / 摘掉、步骤被 `replaces` 撤销，Epic 都不重新推导（只有步骤迁移才会）。
- 检索索引打不开时整个应用起不来（索引本是可丢弃的）；见 bitcask 升级单。
- 系统作用域的整库导出不带 `org_id`，还原后所有项目变孤儿。
- 依赖环检测在菱形依赖图上指数级重复遍历（`Seen` 没在兄弟分支间传递）。

## 已修 · 前端
- **所有 toast 不显示**：迁移 shadcn 后 `SnackbarProvider` 没了，18 个文件还在调 notistack 的 `useSnackbar`（无 Provider 时是空操作）。加 `components/notify.ts` 走 sonner，删掉 notistack 依赖。
- **400 错误被吞**：`useApiError` 对 400 不提示，多数调用点又不看返回值。现在除非调用方声明自己内联显示该字段，否则照常提示。
- Epic 看板拖一张卡，Epic 详情缓存被步骤整个覆盖（页面变成步骤的详情，15 秒后才恢复）。
- 摘掉所属 Epic 不生效（传了 `undefined`，被 JSON 丢掉；约定是 `""`）。
- 行内标题编辑框是空的（没传 `value`）；Esc 不还原。
- 任务间跳转不重置编辑态，可能把 A 的描述草稿存进 B（按任务 id 加 key）。
- 改密输错当前密码被 401 拦截器踢去登录页（后端改回 400 `field=current`；拦截器只认 `error = unauthorized`）。
- 只显示一次的 key 弹层 / 面板可被 Esc、点遮罩误关。
- 顶栏搜索：输入任务 ID 没有跳转项、浅色主题下白字白底、清空时「搜索中…」卡住。
- 任务筛选：防抖回调用旧的筛选值覆盖刚点的状态；切项目后搜索框不跟 URL。
- 删除关联后用旧快照盖回缓存（「被阻塞」多挂一个轮询周期）。
- Markdown 编辑器 200ms 防抖丢最后几个字；`//evil.com` 被当成站内链接；注册第二步的邮箱冲突不可见；任务详情加载失败永远是骨架屏。

## 没动 · 建议
按价值排。

1. **登录 / 发验证码没有限流**：登录可以无限试密码（每次约几十毫秒的 PBKDF2）；发码只按邮箱限 60 秒，不按来源限，可以拿来轰炸任意邮箱。
2. **检索索引从不 merge**：每次改任务追加一篇文档，旧版本一直占着盘。现网两个月 656K，不急；`reindex` 现在会顺带清干净。要做的话是定时 `needs_merge` → `merge`。
3. **bosun_search 是单进程串行**：读写、重建都排一个队，重建期间检索全等着。bitcask 的句柄本身可并发读，可以把句柄放 `persistent_term` 让读直通——但重建时要换句柄，得处理好。
4. **BQL / 列表每次全表扫**：`bosun_bql:query` 把全部任务读出来逐条求值，`blocked` 排序时每次比较都读关联表。任务上万之前不是问题。本次只把可见性检查从逐条改成逐项目。
5. **BQL `feedback_count`** 用的是 `feedback_seq`（含被修订作废的旧版本，docs/BQL.md 是这么写的），而任务摘要里的 `feedback_count` 只数有效条数——两个同名字段口径不同，容易误会。
6. **REST 读接口不看 `read` scope**：只有写接口按 scope 拦；一个只有 `write` 的 key 也能读。MCP 那边读工具是要 `read` 的。
7. **TransitionPanel 先写 Feedback 再迁移**，迁移失败重试会多出一条相同的 Feedback。彻底的做法是 transition 接口收 `feedback`，同一事务落库。
8. **前端样式遗留**：`--md-*` 变量和 hljs 配色随 MUI 一起没了（代码块无高亮、编辑器选区透明）；侧栏 `NavLink` 高亮规则不对；主题状态有三份互不同步。需要对着页面调，没盲改。
9. **前端体积 / 请求**：路由没有懒加载（首屏带上 Query / Data / Org / Account）；写操作后串行等好几个重拉；普通任务详情每次拉 500 条 Epic 摘要。
10. **依赖里没人用的包**：`@radix-ui/react-tabs`、`@radix-ui/react-scroll-area` 及对应的 `ui/*.tsx`；`tsconfig.app.json` 的 `strict: false`。
11. **整库备份不含组织 / 用户 / key**：`export` 是给「搬数据」用的，不是灾备；完整备份要拷 `data/mnesia/`，或者加一个系统作用域的全表导出。
12. **`replaces` 撤销的任务会让依赖它的任务永远 blocked**（依赖只认 DONE / VERIFIED）。是不是该把依赖转给替代者，要产品上定。
