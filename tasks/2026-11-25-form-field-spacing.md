# 表单：标签与输入框挤在一起、焦点框压到标签（新建项目的 Key 等）

日期：2026-11-25　状态：已完成，未提交

## 问题

用户在 `/projects` 新建项目时反馈：点输入框时和上面的「Key」有些冲突。

原因：shadcn 的 `Label` 自己没有外边距，好几个面板直接把 `<Label>` 和 `<Input>` 叠在一起（间距 0），
输入框获得焦点后画在框外 3px 的 focus ring 正好压在标签文字上。同样的写法在：
新建 / 编辑项目（Key、名称）、新建 / 编辑用户（邮箱、显示名、角色、密码）、完成 / 验收面板（提交 hash、命令、结果摘要、历史备注）、
新建任务（标题、标签；同一行里优先级 / 执行人有 `mt-1`、标签没有，输入框上下还错开）。

## 改动

- 新增 `components/FormField.tsx`：标签 / 控件 / 说明或错误，上下各 8px（`grid gap-2`），可带标签右侧附注。上面这四个面板全部改用它。
- 其余用原生 `<label className="mb-1">` 的面板（API Key、关联、筛选器、修改密码）间距从 4px 调到 8px，与之一致。
- `SidePanel` 加 `size`：短表单（项目 / 用户 / 密码 / API Key / 关联 / 筛选器）用 `md`（最宽 36rem），不再占屏幕 2/3；带大段 Markdown 编辑的仍是 `lg`。内容区内边距 12px → 20px，焦点框不会被滚动容器裁掉。
- 新建项目：先填「名称」再填「Key」；Key 输入自动转大写并只留字母数字，标签右侧实时显示任务编号预览（如 `TT9-1、TT9-2…`）；输入中只在以数字开头时提示，「太短 / 没填」留到点创建时再说（以前敲第一个字母就飘红）；（编辑项目见下面第二步）。
- 顺手修：新建任务面板的「取消」按钮漏了 `variant="outline"`（从最初的代码就是这样），和「创建」一样是实心主色，分不清主次。全站其余「取消」都已检查过。
- 验证：前端 54 例 + build；临时实例截图：修改前（Key / 名称标签贴着输入框）、修改后新建项目（填了名称与 Key、编号预览）、空提交的错误提示（暗）、新建用户、新建任务（暗，取消为描边按钮）。

## 第二步：编辑项目改成「项目设置」面板（参照 dashboard 设置页）

- 新增 `features/projects/ProjectSettingsPanel.tsx`，项目页右上角齿轮打开；`ProjectFormDialog` 只管新建。
- 分组：**概况**（创建 / 更新时间，任务、未结、已验收、Epic 四个小卡片，完成度条 = 已验收 / 不含拒绝和撤销；数据来自 `/api/v1/stats?project=KEY`）→ **基本信息**（名称；Key 只读 + 复制按钮 + 编号示例）→ **描述**（Markdown）→ **归档**（红框危险区）。
- 归档 / 取消归档改为即时操作 + 确认框（提示还有几个未结任务），不再混在「保存」里。
- 底栏显示「有未保存的修改 / 没有修改」，没改动时「保存」不可点；有改动时关闭会先问「放弃未保存的修改？」；Ctrl/⌘+Enter 保存。
- 验证：前端 54 例 + build；临时实例截图：设置面板（亮）、改名后关闭的确认（暗）、归档确认框、已归档状态。

## 第三步：新建任务面板（参照 dashboard 任务表单）

- `features/tasks/TaskFormDialog.tsx` 改成左右两栏：左边类型（任务 / Epic 两张可选卡片，带一句说明）、标题（字数、示例占位）、描述（撑满）；右边属性栏：优先级（高 / 中 / 低 分段按钮带图标）、所属 Epic、执行人（复用详情页的 AssigneePicker，可搜可直接输入名字）、标签（回车 / 逗号添加，退格删最后一个，没回车的字创建时也算上）。
- 底栏：「创建后继续新建」（记在 localStorage `bosun.taskform.keepOpen`；建完清空标题和描述、保留属性，页眉显示「本次已建 N 个」，「取消」变「完成」）、Ctrl/⌘+Enter 提示、按钮写明「创建任务 / 创建 Epic」。
- `onCreated` 多一个 `keepOpen` 参数：列表视图下勾了继续新建就不跳到新任务详情。
- 验证：前端 54 例 + build；临时实例截图：空表单（亮）、Epic + 继续新建（暗）、连续建两个任务后的状态。

## 第四步：任务详情页再一轮（参照 dashboard）

新增 `features/tasks/TaskInsights.tsx`，三块概览接进 `pages/TaskDetailPage.tsx`：

- **需要注意的事**（标题下、两栏之上，没事不显示）：被依赖挡住时列出挡路的任务（编号 / 标题 / 状态，可点），解释「开始」为什么按不了；有提问待回答时显示提问摘录 +「去回答」（滚到那条提问闪一下、光标进回答框）。两条都有时并排，只有一条时占满。
- **进度**（主栏第一块）：新建 → 进行中 → 已完成 → 已验收 四步条，每步写最近一次到达的人和时间，当前步标「当前」，页眉写「已持续 X、共 N 次状态变更」，有打回时右上角「打回 N 次」；拒绝 / 撤销时末尾加终止步（带说明），没走到的步变灰。
- **交付**（右栏，替换原「提交」卡片）：最近一次测试证据（通过 / 未通过、摘要、命令、谁在哪个状态记录的）+ 全部提交（可复制）。
- 注意：接口返回的 `history` 是**新的在前**；TaskInsights 里先按 `at` 升序排再取「最近一次」，不依赖接口顺序（第一次截图就因为这个取成了较早的「12 passed」）。
- 新增 `test/TaskInsights.test.tsx` 4 例（最近测试证据不受接口顺序影响、打回次数与当前步、撤销终止步、阻塞列表只列未完成的依赖 / 无事不渲染）。前端 58 例 + build；临时实例截图：被阻塞（亮）、打回 + 待回答 + 交付（暗 / 亮）、已撤销。
