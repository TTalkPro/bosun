# API Key 安全轮换与审计

## 背景
当前 Key 泄露后只能撤销再重建，Agent 配置中的项目范围、scopes 和过期时间需要手工重录；
历史 Key 也没有轮换时间，无法区分“首次创建”和“当前秘密值签发”。

## 目标
- 保留 Key 配置、撤销历史和审计语义，同时生成新的明文秘密值。
- 只允许轮换 active Key；已撤销 Key 直接返回 `not_found`。
- 记录 `rotated_at`；轮换后重置 `last_used_at`，表示新秘密值尚未使用。
- REST 返回完整的新 Key 明文，且仍然只显示一次。
- 前端在账户页提供轮换入口，成功后展示新明文和保存提醒。

## 非目标
- 不保留多代秘密值并行有效；轮换立即让旧 Key 失效。
- 不新增全局审计日志表；当前以 Key 自身生命周期字段作为最小可用审计。

## 验收
- `POST /api/v1/keys/:id/rotate` 返回 201 和新明文。
- 旧明文立刻 401，新明文可认证。
- name / scopes / project 白名单 / 原创建时间保持不变。
- `rotated_at` 存在，`last_used_at` 为空。
- 已撤销 Key 轮换返回 404。
